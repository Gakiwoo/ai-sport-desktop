# 跳绳精准计数算法调研报告

> 2026-07-13 复核：本文仍作为算法改进方向参考，不是当前准确率证明。真实视频数据仍为 0/500，任何方案进入产品承诺前都必须经过统一数据集、误检/漏检和失败样例验收。

## 一、当前问题诊断

当前 `JumpRopeCounter.ts` 存在以下导致"骨骼点稍微移动即可计数"的问题：

| 问题 | 原因 | 影响 |
|------|------|------|
| `minPeakHeight: 0.015` 太低 | 归一化坐标下 0.015 仅约 8-10px，正常站立晃动就可能触发 | 身体微动就计数 |
| 只用峰值检测，无状态机 | 缺少"落地→起跳→空中→落地"的完整周期验证 | 单方向抖动就能骗过 |
| 窗口仅 30 帧 | 约 1 秒，不能覆盖慢速跳绳的完整周期 | 短暂波动被误判为跳跃 |
| 无"双脚离地"验证 | 没有检查脚踝是否真的离开了站立面 | 抬脚或弯腰就计数 |
| 基线是静态的 | 校准后不再更新，如果用户改变站立深度会失效 | 深度变化导致误触发 |

## 二、开源方案调研

### 方案 A：chenwr727/RopeSkippingCounter（GitHub）

**核心思路：** 肩+髋 Y 轴中心追踪 + 状态机 + 迟滞防抖

**关键设计：**
- **骨骼点选取：** 23(左髋)、24(右髋)、11(左肩)、12(右肩) 四点均值
- **数据平滑：** EMA（指数移动平均），α=0.5
- **滑动窗口：** 50 帧计算窗口内 max/min
- **状态机：** 追踪 Y 轴波峰波谷，完成一次"下降→上升→下降"完整周期计一次
- **迟滞阈值（关键！）：**
  - `up_ratio = 0.55`：上升幅度达到波动区间 55% 才认为到达高点
  - `down_ratio = 0.35`：下降达到 35% 才认为回到低点
  - 防止在边界抖动导致频繁翻转

**优点：** 简单、实时性好、不依赖绝对位移
**缺点：** 没有区分跳绳和原地蹦跳

### 方案 B：基于轻量级姿态估计的跳绳检测算法（CSA 学术论文 2023）

**核心思路：** 帧间差分提取关键帧 + 关节检测 + 跳跃周期验证

**关键设计：**
- 帧间差分法检测运动帧，减少无效帧的推理开销
- 使用踝关节(27,28) Y 坐标变化量判断"双脚离地"
- 设定最小跳跃高度阈值（基于人体比例的自适应阈值）
- 要求完整的"起跳→滞空→落地"三个阶段

**优点：** 计算量小、适合嵌入式部署
**缺点：** 帧间差分对光线变化敏感

### 方案 C：ROPEVISION（Springer 2025，越南团队）

**核心思路：** MediaPipe Pose 特征提取 + LSTM 时序分类

**关键设计：**
- MediaPipe 提取 33 个骨骼点的 (x, y, visibility) 作为特征
- LSTM 网络学习跳绳动作的时序模式
- 可识别跳绳技术类型（单摇、双摇、交叉跳等）
- 计数与动作识别解耦

**优点：** 最精准、可扩展到多种花样跳绳
**缺点：** 需要训练数据集、LSTM 推理增加延迟、不适合轻量级桌面应用

### 方案 D：Dylan Plummer 竞技跳绳计数器

**核心思路：** YOLOv8-Pose 关节检测 + 垂直位移追踪

**关键设计：**
- 追踪脚踝和髋部的 Y 坐标
- 计算脚踝相对于髋部的距离变化（归一化，适应不同距离）
- 跳跃高度需超过站立时脚踝-髋部距离的一定比例
- 状态机：on_ground → ascending → airborne → descending → landing

## 三、推荐算法方案

综合以上调研，结合项目是轻量级桌面应用的定位，推荐 **"状态机 + 多条件联合验证"** 方案（方案 A+B+D 的融合）：

### 核心原则

> **一次有效跳绳 = 完整的"站立→双脚离地→滞空→落地"周期**

### 状态机设计（4 状态）

```
                    脚踝 Y < 基线 - 离地阈值
                    且 身体在上升
  ┌──────────┐     ─────────────────────────     ┌──────────┐
  │  STANDING │ ───────────────────────────────→ │ ASCENDING │
  │  (站立)   │                                  │  (上升)   │
  └──────────┘                                  └──────────┘
       ↑                                              │
       │              到达最高点（速度变号）             │
       │          ─────────────────────────            │
       │                                              ↓
  ┌──────────┐     ─────────────────────────     ┌──────────┐
  │  LANDING  │ ←─────────────────────────────── │ AIRBORNE  │
  │  (落地)   │                                  │  (滞空)   │
  └──────────┘     脚踝 Y > 基线 - 落地阈值       └──────────┘
       │          且 滞空时间 >= 最小滞空帧         ↑
       │          ─────────────────────────        │
       ↓                                              │
    count++                             到达最高点（Y 最小）
   (计数完成)                        ─────────────────────────
```

### 关键判定指标

| 指标 | 说明 | 阈值策略 |
|------|------|----------|
| **踝关节离地位移** | 踝关节 Y 相对于站立基线的上移量 | >= 身体高度（肩到踝）× 8%（自适应） |
| **垂直速度** | 身体中心 Y 的帧间差分 | 需要有明确的上升→下降方向变化 |
| **最小滞空帧数** | 从离地到落地之间的帧数 | >= 3 帧（约 100ms@30fps） |
| **最大滞空帧数** | 单次跳跃的最大允许时间 | <= 30 帧（约 1 秒，过滤走动/蹲下） |
| **最小跳跃间隔** | 两次计数之间的最小帧数 | >= 6 帧（约 200ms，过滤快速抖动） |

### 骨骼点选取（精简但可靠）

| 用途 | 骨骼点 | 理由 |
|------|--------|------|
| 身体中心 Y | 左肩(11) + 右肩(12) + 左髋(23) + 右髋(24) | 四点均值，最稳定 |
| 离地判断 | 左踝(27) + 右踝(28) | 直接反映脚是否离地 |
| 身体比例 | 肩到踝的距离 | 用于自适应阈值计算 |
| 可选：跳绳手 | 左腕(15) + 右腕(16) | 辅助判断是否在跳绳（手在转动） |

### 与当前代码的关键差异

| 当前实现 | 改进方案 |
|----------|----------|
| 单点峰值检测 | 4 状态机，需完整周期 |
| `minPeakHeight: 0.015`（绝对值） | 自适应阈值（基于身体比例） |
| 无离地验证 | 踝关节必须相对基线上移 >= 身高 8% |
| 无滞空时间验证 | 最少滞空 3 帧 |
| 30 帧窗口 | 60 帧窗口 + 实时状态机 |

## 五、实施建议

**优先级 P0（立即改进）：**
1. 重写为 4 状态机（STANDING → ASCENDING → AIRBORNE → LANDING）
2. 添加踝关节离地位移验证（>= 身高 8%）
3. 添加最小滞空帧数验证（>= 3 帧）
4. 自适应阈值（基于校准期的肩-踝距离）

**优先级 P1（后续优化）：**
5. 可选：手腕旋转检测（区分跳绳和原地蹦跳）
6. 动态基线更新（适应深度变化）
7. 跳绳节奏检测（异常快/慢时提示）
